[h2] Built for people whose work does not fit in one list
[p] Most life tools are either a generic task list you have to reshape around your life, or a workspace so broad that maintaining it becomes the work. The Mainframe starts from the lists a person actually keeps: studies, builds, acquisitions, long-term goals, and ventures.
[h3] Developers and solo builders
[p] Several builds, courses, and side projects running in parallel with no single place that shows all of them.
[h3] Students and career switchers
[p] Certification tracks, study material, and application deadlines spread across notes, browsers, and messages.
[h3] Freelancers and creators
[p] Client deliverables that recur, personal work that keeps getting postponed, and ideas that need somewhere to land.
[h3] Anyone whose lists are everywhere
[p] Task content split across note apps, chat threads, spreadsheets, and memory. The Mainframe is built to be the one place those lists come to rest.
[h2] Paste, structure, decide, continue
[p] Four steps, no setup ritual. The loop works the same offline as it does on a local network.

[h2] Four things it does, and nothing else
[p] Each pillar is a commitment about behavior, not a feature count. Technical detail belongs further down the page.
[h3] Bring in a list
[p] Paste messy plain text and start with structure. No template to fill in, no import wizard, and the source line stays attached to the row it produced.
[h3] See what matters now
[p] One combined view across every domain so parallel tracks stop competing for attention in your head. Each suggestion explains why it appeared.
[h3] Keep it local
[p] Offline-first SQLite storage with no required account. Your database is a file on your own device, not a row in someone else's service.
[h3] Move a snapshot when you choose
[p] Opt-in transfer between your own trusted devices with one-time pairing, bounded to a validated snapshot rather than continuous background sync.

[h2] What it will not do, and what you should know
[p] Two different lists. The first is what the app will never do to you. The second is what is genuinely limited today — stated plainly, because you should know it before you put real work in.
[h3] What it will not do
[h3] No required account or cloud service
[p] The core workflow never calls a hosted backend. There is no sign-up, no subscription, and no telemetry service in the loop.
[h3] Data stays on the device by default
[p] Every device holds its own SQLite database and works with no network connection.
[h3] No background sync
[p] Nothing moves between your devices unless you start a transfer yourself and pair once to authorise it.
[h3] Nothing is uploaded to build this page
[p] This is a static page with no third-party scripts and no external fonts. The only measurement is the host's own cookie-free page-view counter — no accounts, no cross-site tracking, no personal data.
[h3] What you should know before trusting it
[h3] Devices do not merge automatically
[p] Installing the app on a second machine does not combine the two databases. A snapshot transfer copies one device's database over the other's — it is not a merge.
[h3] The current LAN transport is cleartext
[p] Sync is HTTP on the local network, restricted to private addresses on port 9377 (discovery on 9378). Do not expose it to the public internet, use it on an untrusted network, or treat it as a backup.
[h3] Pairing is short-lived by design
[p] Pairing uses a one-time six-digit token that expires after 10 minutes. If pairing fails, start over rather than reusing a token.
[h3] Back up before replacing a local database
[p] A snapshot transfer replaces the target database. Export a backup first if the device holds anything you have not duplicated elsewhere.
[h3] Desktop builds are unsigned
[p] Until platform signing is configured, desktop artifacts are unsigned and will trigger an operating-system warning on first launch. Only run a build you downloaded from this repository's own Actions tab.
