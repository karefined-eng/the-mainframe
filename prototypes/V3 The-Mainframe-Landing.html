A local-first home for every list you are already keeping.

The Mainframe is a private, offline life-management app for scattered projects, goals, courses, ideas, and purchases. Paste the lists you already have, keep the database on your own devices, and bring some order to what is currently spread across notes, messages, and memory.

Built for people whose work does not fit in one list

Most life tools are either a generic task list you have to reshape around your life, or a workspace so broad that maintaining it becomes the work. The Mainframe starts from the lists a person actually keeps: studies, builds, acquisitions, long-term goals, and ventures.

Developers and solo builders

Several builds, courses, and side projects running in parallel with no single place that shows all of them.

Students and career switchers

Certification tracks, study material, and application deadlines spread across notes, browsers, and messages.

Freelancers and creators

Client deliverables that recur, personal work that keeps getting postponed, and ideas that need somewhere to land.

Anyone whose lists are everywhere

Task content split across note apps, chat threads, spreadsheets, and memory. The Mainframe is built to be the one place those lists come to rest.

Paste, structure, decide, continue

Four steps, no setup ritual. The loop works the same offline as it does on a local network.

01

Paste the list you already have

Copy a wall of unstructured text from wherever it currently lives and paste it in. Plain text is the only input path — there is no file-upload workflow and no format-specific parser to satisfy.

02

Watch it become rows

Each non-empty line becomes one item, with the original line kept alongside it as raw import text. That is the whole transform: the app does not guess which domain a line belongs to, and it does not invent a due date for you.

03

See what needs attention

The dashboard pulls a short cross-domain shortlist and says why each entry surfaced, using plain reasons such as being overdue, being due this week, or not having been touched in a while.

04

Stay offline, sync only when you choose

The app reads and writes a local SQLite database on each device. When you want the same snapshot on a second device, pair once on a trusted local network and transfer a validated snapshot.

Four things it does, and nothing else

Each pillar is a commitment about behavior, not a feature count. Technical detail belongs further down the page.

Bring in a list

Paste messy plain text and start with structure. No template to fill in, no import wizard, and the source line stays attached to the row it produced.

See what matters now

One combined view across every domain so parallel tracks stop competing for attention in your head. Each suggestion explains why it appeared.

Keep it local

Offline-first SQLite storage with no required account. Your database is a file on your own device, not a row in someone else's service.

Move a snapshot when you choose

Opt-in transfer between your own trusted devices with one-time pairing, bounded to a validated snapshot rather than continuous background sync.

What it will not do, and what you should know

Two different lists. The first is what the app will never do to you. The second is what is genuinely limited today — stated plainly, because you should know it before you put real work in.

What it will not do

No required account or cloud service

The core workflow never calls a hosted backend. There is no sign-up, no subscription, and no telemetry service in the loop.

Data stays on the device by default

Every device holds its own SQLite database and works with no network connection.

No background sync

Nothing moves between your devices unless you start a transfer yourself and pair once to authorise it.

Nothing is uploaded to build this page

This is a static page. It loads no third-party scripts, no analytics, and no external fonts.

What you should know before trusting it

Devices do not merge automatically

Installing the app on a second machine does not combine the two databases. A snapshot transfer copies one device's database over the other's — it is not a merge.

The current LAN transport is cleartext

Sync is HTTP on the local network, restricted to private addresses on port 9377 (discovery on 9378). Do not expose it to the public internet, use it on an untrusted network, or treat it as a backup.

Pairing is short-lived by design

Pairing uses a one-time six-digit token that expires after 10 minutes. If pairing fails, start over rather than reusing a token.

Back up before replacing a local database

A snapshot transfer replaces the target database. Export a backup first if the device holds anything you have not duplicated elsewhere.

Desktop builds are unsigned

Until platform signing is configured, desktop artifacts are unsigned and will trigger an operating-system warning on first launch. Only run a build you downloaded from this repository's own Actions tab.

Read the code before you trust it

The source is public, and the claims above are checkable in it. Issues and focused pull requests are welcome — the limitations are as open to discussion as the features.

  • Include the platform, the app version or commit, reproduction steps, and relevant logs.
  • Keep reports specific — a narrow bug with clear steps is more useful than a broad feature wish.
  • Do not attach database files or other private data to an issue. Sanitize screenshots first.
  • Ideas and limitations are equally welcome. This is an early public release and the roadmap is still open.
  • Report a problem or ask a question in the issue tracker.
